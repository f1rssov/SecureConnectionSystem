# SecureConnectionSystem
# Система безопасного соединения для незащищенных приложений (Secure Connection System for Unprotected Applications)

[![Go version](https://img.shields.io/github/go-mod/go-version/your-username/your-repo)](https://golang.org)

## 📜 О проекте

Это дипломный проект, выполненный в **Российском государственном университете им. А.Н. Косыгина**.

**Цель проекта** — создать простую в использовании систему, которая обеспечивает безопасную передачу данных для любых приложений, даже если они не поддерживают шифрование. Система автоматически создает защищенный **SSH-туннель** и перенаправляет весь трафик через локальный **SOCKS5-прокси**. Это идеальное решение для защиты от перехвата данных (сниффинга) и атак "человек посередине" (MITM) при работе в небезопасных сетях, таких как публичные Wi-Fi точки.

## ✨ Ключевые возможности

* **🛡️ Надёжная безопасность**: Используется аутентификация по публичным ключам и стойкое шифрование SSH для защиты всего трафика.
* **🤖 Полная автоматизация**: Забудьте о ручной настройке SSH и прокси. Одна команда делает всё за вас.
* **🌐 Универсальность**: Перенаправляет трафик любых TCP-приложений (браузеры, мессенджеры, клиенты баз данных) через защищенный канал.
* **🚀 Простота использования**: Запустите клиент и автоматически откройте браузер, уже настроенный для безопасной работы.
* **💻 Кроссплатформенность**: Написан на языке Go, что позволяет легко скомпилировать и запустить его на Windows, macOS и Linux.
* **🔒 Полный контроль**: Вы контролируете и клиент, и сервер. Никакого доверия третьим сторонам и сомнительным VPN-сервисам.

## 🏗️ Архитектура системы

Система состоит из двух основных компонентов: **SSH-клиента**, работающего на вашем компьютере, и **SSH-сервера**, развернутого на удаленной машине (например, VPS).

**Поток данных выглядит так:**

1.  **Браузер** (или другое приложение) отправляет трафик на локальный SOCKS5-прокси (`127.0.0.1:1080`).
2.  **SSH-клиент** перехватывает этот трафик, шифрует его и отправляет через SSH-туннель на сервер.
3.  **SSH-сервер** расшифровывает трафик и отправляет его в интернет от своего имени.
4.  Ответ от целевого сайта проходит тот же путь в обратном направлении, обеспечивая полную защиту.


## 🚀 Начало работы

### Предварительные требования

1.  **Go**: Установленный язык Go (версия 1.18+).
2.  **Git**: Для клонирования репозитория.
3.  **Удаленный сервер (VPS)**: Любой виртуальный сервер с доступом по SSH (в проекте использовался Yandex.Cloud).

### Установка и запуск

1.  **Клонируйте репозиторий:**
    ```bash
    git clone [https://github.com/your-username/your-repo.git](https://github.com/your-username/your-repo.git)
    cd your-repo
    ```

2.  **Сгенерируйте SSH-ключи:**
    Эта команда создаст ключи для клиента и сервера в директории `./keys`.
    ```bash
    make keys
    ```

3.  **Соберите бинарные файлы:**
    ```bash
    make build
    ```

4.  **Разверните сервер на вашем VPS (на примере Yandex.Cloud):**
    Замените `user@your-vps-ip` на ваши данные. Эта команда скопирует серверный бинарник и ключи на ваш VPS, после чего запустит его в фоновом режиме.
    ```bash
    make yandex-server-start SSH_USER=user SSH_HOST=your-vps-ip
    ```
    Вы можете проверить логи сервера командой:
    ```bash
    ssh user@your-vps-ip "tail -f server.log"
    ```

5.  **Запустите клиентское приложение:**
    Эта команда запустит локальный клиент, который подключится к вашему серверу, поднимет SOCKS5-прокси и откроет новое окно Google Chrome, уже настроенное для работы через защищенный туннель.
    ```bash
    make yandex-start-connection SSH_HOST=your-vps-ip
    ```

    🎉 **Готово!** Весь трафик в открытом окне Chrome теперь защищен. Вы можете проверить свой IP-адрес на сайте вроде [whoer.net](https://whoer.net) — он должен совпадать с IP вашего сервера.

## ⚙️ Автоматизация с Makefile

`Makefile` — это сердце автоматизации проекта. Вот основные команды:

* `make keys`: Генерирует SSH-ключи для клиента и сервера.
* `make build`: Компилирует клиентский и серверный бинарники.
* `make run`: Полный локальный запуск (сервер и клиент на одной машине для теста).
* `make yandex-server-start`: Разворачивает и запускает сервер на удаленном хосте.
* `make yandex-start-connection`: Запускает клиент для подключения к удаленному серверу.
* `make clean`: Удаляет сгенерированные бинарники и ключи.
* `make fclean`: Полная очистка, включая Docker-образы (если использовались).

## 🛡️ Модель безопасности

Этот проект разработан с акцентом на безопасность:

* **Аутентификация только по ключам**: Подключение по паролю полностью отключено, что защищает от атак перебора.
* **Защита от MITM**: Клиент строго проверяет публичный ключ сервера при подключении. Если ключ не совпадает с ожидаемым, соединение немедленно разрывается.
* **Изоляция**: SSH-сервер настроен так, что не предоставляет доступ к командной оболочке. Его единственная задача — безопасно перенаправлять трафик.
* **Конфиденциальность**: Весь трафик между клиентом и сервером надежно шифруется протоколом SSH.
